Test version of the new `nvidia-prolapse` mode: an open-source NVIDIA driver running right inside Android.

## What's new

- **Faster on RTX 50 series.** 3DMark Wild Life Extreme on an RTX 5090 (driver 615.78.08), all runs in the same
  session: rc11 428.1 FPS, this build 464.5 FPS (+8.5 %). NVIDIA's own driver inside Android scored 493.5 FPS.
  The gains come from:
  - the shader compiler, which now produces faster code for loops and, on RTX 50 series, for texture fetches;
  - the async compute queue (next item);
  - ZCULL, the GPU's coarse depth test that skips hidden pixels early, which is now turned on (+3.6 % in the
    Wild Life Extreme score on its own);
  - compute dispatches that now use the same GPU settings as NVIDIA's driver.

  Other GPUs were not measured for this release.
- **Async compute queue.** Vulkan apps get a second queue family for compute and transfers whose work runs on the
  GPU at the same time as the graphics queue's, as with NVIDIA's own driver.
  <!-- TODO: per-generation wording (which GPUs have the queue), filled in after the cross-generation runs. -->
- **Fewer GPU stalls on RTX 50 series.** Two kinds of Vulkan barriers no longer wait for the whole GPU to go idle,
  as with NVIDIA's own driver: a render-target write followed by a read in a fragment shader (pixel-shader barrier),
  and one compute dispatch followed by another (dispatches ordered through a join QMD). Other GPUs keep the full
  wait for these for now. No measurable change in Wild Life Extreme.
- **glibc-shim mode for package users.** `sudo waydroid-nvidia-setup --mode glibc-shim` runs your host's own NVIDIA
  driver inside Android. It runs on drivers 550 to 615 with the open or the closed kernel module; tested on 615 with
  the open module, and on rented machines with the closed module on 550, 570 and 580 (RTX 3070, RTX 3090, RTX 4080
  SUPER), earlier also with 570 open and 595 closed: setup check, Android boots with its compositor on NVIDIA's Vulkan driver, our
  in-Android Vulkan tests pass. Driver 535 is refused with the reason: its Vulkan driver cannot pass fences as
  sync_files, which Android needs to hand buffers between apps and the compositor. The setup finds the driver's libraries wherever your distribution installs
  them, checks them against the shims of this release, and names the package to install when the 32-bit driver
  libraries are missing. NVIDIA's own GLES (`--native-gl on`) needs driver 570 or newer. Drivers 470 and older are
  refused with the reason.
- **glibc-shim on drivers 550 to 560 and 580: buffer acquire waits on the CPU (known limitation).** Two bugs in
  NVIDIA's driver with imported sync_files would crash an app (550 to 560) or leak a file descriptor per frame until
  the app runs out (580). On those drivers, when an app takes the next buffer from its window, it now waits until the
  compositor has released that buffer instead of handing the wait to the GPU. Its frame-time cost was not measured
  yet. Other driver branches are unaffected.
- **glibc-shim mode: 3DMark Wild Life Extreme no longer crashes when it starts.**

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/Shiro836/waydroid-nvidia/public-test/packaging/install.sh | sudo bash
sudo waydroid-nvidia-setup
waydroid session start
```

For Google apps on a new install, use `sudo waydroid-nvidia-setup -s GAPPS`. Updating from an earlier rc is the same
commands. Supported GPUs, drivers and known issues are in the
[README](https://github.com/Shiro836/waydroid-nvidia/tree/public-test#readme).
