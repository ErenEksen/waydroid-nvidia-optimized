# Venus mode development loop

A fast edit, build, deploy and measure loop for the Venus mode components (guest Mesa, virglrenderer, gralloc,
hwcomposer). For one-off builds see [building.md](building.md); for the native modes see
[dev-setup.md](dev-setup.md).

## One-time setup

The loop builds from persistent upstream checkouts. Default layout (every path can be changed through the
variables in `dev/env.sh`):

```sh
WNV=~/repos/waydroid-nv
git clone https://gitlab.freedesktop.org/mesa/mesa.git            $WNV/mesa
git clone https://gitlab.freedesktop.org/virgl/virglrenderer.git  $WNV/virglrenderer
git clone https://github.com/waydroid/android_hardware_waydroid   $WNV/hwcomposer-src
git clone https://github.com/waydroid/waydroid                    ~/repos/waydroid
```

Check each out at its pinned base (`patches/*/BASE`, full SHAs in `packaging/ci/pins.env`) and apply the
matching `patches/` series. For hwcomposer run `hwcomposer/provision.sh` once. You also need the Android NDK
(`NDK`, default `/opt/android-ndk`).

Deploying needs root writes into `/var/lib/waydroid`. Install the validating helper and allow only that:

```sh
sudo install -Dm755 packaging/host/wd-deploy /usr/local/sbin/wd-deploy
```

```
# visudo -f /etc/sudoers.d/waydroid-dev
yourname ALL=(root) NOPASSWD: /usr/local/sbin/wd-deploy *
yourname ALL=(root) NOPASSWD: /usr/bin/lxc-attach -P /var/lib/waydroid/lxc -n waydroid *
yourname ALL=(root) NOPASSWD: /usr/bin/lxc-info *
yourname ALL=(root) NOPASSWD: /usr/bin/systemctl start waydroid-container.service, \
    /usr/bin/systemctl stop waydroid-container.service, \
    /usr/bin/systemctl restart waydroid-container.service
```

Keep `waydroid upgrade` and wildcard file writes out of NOPASSWD; both are easy root escalations. Run
`sudo waydroid-nvidia-setup --mode venus` once before the first deploy so the guest library mounts are in place.

## The loop

```sh
dev/build <mesa|virgl|hwc|gralloc|angle>   # incremental build; append -x86 or -x86_64 for one ABI
dev/deploy <component>                     # copy into /var/lib/waydroid through wd-deploy
dev/restart                                # restart the whole stack
dev/health                                 # window up, GLES on Venus, no crashes
dev/measure                                # launcher fling benchmark (frame percentiles)
dev/iter                                   # all of the above
dev/status, dev/logs [gfx|units]           # state and filtered logs
dev/sync-patches                           # regenerate patches/ and src/ from the trees
```

Rules:

- Always restart the whole stack after a deploy. Running processes keep the old library, and restarting
  SurfaceFlinger or the composer alone leaves a dead display.
- Bind-mount targets must be real files in the image, not symlinks.
- New mounts and properties belong in the generators (`lxc.py`, `waydroid.cfg [properties]`). Hand edits to
  `config_nodes` or `waydroid_base.prop` are lost on `waydroid upgrade`.
- `patches/` is generated by `dev/sync-patches`; don't edit it by hand. `src/` is the canonical copy.
- Change one thing, restart, measure. Back claims with numbers or a `waydroid shell screencap`.
- Tests pick the GPU by PCI vendor or driver ID, never by a `/dev/dri` node path.

## Useful commands

```sh
sudo lxc-attach -P /var/lib/waydroid/lxc -n waydroid --clear-env \
  -v PATH=/system/bin -- /system/bin/sh -c 'getprop ro.hardware.gralloc'   # run a command in the guest
sudo waydroid shell -- logcat -d -b crash | grep -c Cmdline                  # crash count, want 0
journalctl --user -u wd-venus -f                                             # host renderer log
sudo waydroid shell -- logcat -G 16M                                         # bigger log buffer (per boot)
```

Guest test programs build with the NDK clang (`x86_64-linux-android34-clang`, `i686-linux-android34-clang`) and
go to `~/.local/share/waydroid/data/local/tmp/`, which is `/data/local/tmp` in the guest.
